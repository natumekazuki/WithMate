# WithMate v7.0.0-preview.7

- Version: `7.0.0-preview.7`
- Tag: `v7.0.0-preview.7`
- 公開元: `feat/v7.0.0`

Session metadataの保守責務を分離し、Memory／Character Affectの専用機構を廃止したpreviewです。`v7.0.0-preview.6`からの変更を収録します。

## 変更内容

- SessionのTitleは目的・主題・担当対象を識別する短い名前、Descriptionは担当範囲と現在の状況として扱うよう、promptとMCP／CLIの説明を揃えました。進捗だけでTitleを書き換えず、目的や対象が変わった場合に更新します（[#951](https://github.com/natumekazuki/WithMate/issues/951)）。
- Characterの出力境界、tool実行前の応答、Session metadata保守の固定案内を短縮しました。Character定義、Workspace、Session Role、動的なmetadata・来歴・Timing等の情報は保持します。
- 一般Memory、Character Memory／episode、Character Affectを、専用UI・設定・MCP／CLI・Character context／Affect投影・背景実行・専用History入口・診断・暗号化添付管理とともに廃止しました。互換stubや代替の記憶・感情storeは設けません。
- 通常Session／Auxiliaryと履歴読取、Character定義・editor・snapshot、Timing、Session Graph、Repository Glossary、Prompt Template／Pickerは維持します。共有runtimeの認可・binding・storage generation失効・取消も維持します。

## 互換性・移行

- **更新版の通常起動時、Memory／Affect専用の保存データを退避なしで破棄します。** 専用table・本文・event・episode・version／idempotency等の付随行、専用設定、管理対象の暗号化添付・keyringが対象です。fresh DBにも専用機構は作らず、破棄したデータを旧sourceから再取込・再生成しません。
- 通常Session・会話／操作履歴・Character資産・Timing・Graph・Glossary・project_scopes、共有DB・file／blobを保持します。V4元DB、元の取込file、利用者がexportしたfileは専用データ破棄の対象外です。
- 専用fileの削除とSQL更新は一体のtransactionではありません。途中失敗時は起動を拒否し、SQLをrollbackして次回起動で残件を再試行しますが、既に削除したfileは戻りません。
- 削除前commit `e60cee1cc31a805be29bfa42c98bddce6a6f113e`はコードの復元元であり、データbackupではありません。コードを戻しても破棄済みの記録・添付は復旧できません。
- Memoryによる過去の経験・判断の能動想起、Character episodeの継続、Affectの保存・時間減衰・afterglowは失われます。Character表現は定義と現在の会話文脈に依存し、通常履歴・Graph・Glossaryが同じ体験を代替する保証はありません。
- 製品外のAGENTS／guide／Skill、Character pack、外部Provider設定、既設POSIX shim／Windows aliasは変更・清掃しません。製品外ルールに残る旧tool参照のために、廃止した入口を提供することはありません。
- 実DB・稼働アプリには今回適用していません。専用データの破棄は更新版を起動した際に実行されます。Windows x64向け未署名NSIS installerのインストールや稼働アプリの置換・再起動は自動で行いません。

## 既知の注意

- 通常の`File → Exit`後に`before-quit`が反復し、プロセスとuserData lockが残る既知不具合があります（[#952](https://github.com/natumekazuki/WithMate/issues/952)）。今回は修正を含まず、公開後に別途対応します。直接観測は固定ソース`fd0adc421b6ad2966b08488919542ed3d6d2afaa`の分離した合成profileであり、このNSISでの再現確認ではありません。

## 検証結果

- Memory／Affect撤去の受入時に、必要なproduction・script・test型検査、SQLite owner・依存境界check、renderer・PDF reader・Main・3 CLI build、変更対象別70 test filesを確認しました。保存層・共有runtimeの独立reviewと全test変更の意味審査、採用指摘の修正確認も受入済みです。全repositoryの`npm test`成功を示すものではありません。
- Session／Graph／Glossaryの配布CLI・MCPから実runtime／applicationとsynthetic storageを通る正常・認可拒否・取消・回復経路を確認しました。Settingsはproduction component／CSSとsynthetic propsの非表示描画で確認しており、実IPC・稼働アプリでの確認とは区別します。
- `7.0.0-preview.7`で型検査とSQLite owner・依存境界checkを再実行し、packaging設定・native依存準備・専用データ撤去・metadata・promptの5 test files／24 testsが成功しました。
- renderer・PDF reader・Main・3 CLIをbuildし、古い生成JavaScriptを分離してMainを再buildした出力から、Windows x64未署名NSISを生成しました。installerは682,751,620 bytes、blockmapは713,220 bytesです。既存のchunk size警告があります。
- packaged Electron `44.10.1`のNode modeで、ASARの版・入口とbuild出力1,246 filesの一致、撤去済みruntime／Affect serviceと旧Memory／Character context配布入口の不在、3 CLIのhelp／schema、4 Provider binaryの配置、`node-pty`・`koffi`のnative loadを確認しました。Node modeではCrashpadのアクセス拒否診断が出ましたが、probeとCLIはexit 0でした。
- NSISを実行せずpayloadからASAR・app executable・3 CLIを抽出し、検証したunpacked出力とのbyte一致を確認しました。インストール・GUI起動・通常Exitの実確認は含みません。
