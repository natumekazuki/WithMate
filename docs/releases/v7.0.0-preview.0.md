# WithMate v7.0.0-preview.0

- Version: `7.0.0-preview.0`
- Tag: `v7.0.0-preview.0`
- 公開元: `feat/v7.0.0`

Roleを持つ通常Session同士が、依頼・相談・報告を非同期にやり取りする最初のV7 previewです。v6.5.0からの変更を収録し、同じCrewでSession Graphと資料を共有しながら、各Sessionが独立して作業を進められます。

## 変更内容

### Role付きSessionと非同期連携

- Standalone・全体統括・個別統括・Worker・Auxiliaryを識別し、同じ起点の通常Sessionと各AuxiliaryをCrewとして扱います。通常子の作成時に、親がWorkspaceとProvider・Model等の実行設定を指定できます。
- 通常Sessionの実直属親子間で依頼・追加指示・報告を送信できます。受理した仕事は送信元のTurn終了後も継続し、明示的な報告を受けた親は追加のユーザーSendなしで次のTurnを開始できます。
- 即時配送と、送信元Turnの終端・結果保存後に処理を開始する`after_source_turn`を選択できます。後者の待機で、別の即時入力を塞ぎません。
- GUIとMCP／CLIの入力を共通の永続queueへ接続しました。受付、待機中の編集・並べ替え、CodexへのSteer、開始入力と追加入力、実行結果を同じ受付・Turnから確認できます。
- 保存済みの受付・Turn・応答・操作・成果物を、仕事を再実行せず取得できます。公開情報の探索は自Crewが既定で、別Crew・全Crewも明示して参照できます。読取可能であることは、任意Sessionへの送信・変更許可を意味しません。
- 共通Session MCPをCodex・Copilot・Claude・OpenCodeへ接続し、Windows配布物に`withmate-session.cmd`を追加しました。

### Coordinationと操作画面

- 作業上の相談をCoordinationへ起票し、呼び出し元への相談、ユーザーへの引継ぎ、回答配送、取り下げ・訂正を保存します。Provider自身の質問・承認とは分離しています。
- MonitorのCoordination枠から起票元Sessionへ移動し、既存の右ペインで相談を選び、本文・回答を確認して対応できます。Monitorの実行状態表示とCoordination表示を分けました。
- 回答は起票元が取得する前まで変更でき、Turn入力または起票元のMCP／CLI取得で確定します。取得済み、利用済み、相談の解決は別の状態です。取り下げても受理済み回答を消しません。
- 会話の送受信者と宛先メンションを区別し、送信側の相対ファイルリンク・ローカル画像を送信元の参照先へ接続しました。入力原文・採用入力・保存済み実行設定は応答のDetailsから確認できます。
- Agent作成の子WindowとRestore Sessionsの復元Windowは最小化で用意します。復元途中の未処理対象の消失と、初期snapshot読込失敗後に復元できなくなる問題を修正しました。

### Crewの共有と継続

- Crew内の通常SessionとAuxiliaryは、初回接続から同じ起点のSession Graphを参照・更新します。別CrewのGraphは明示指定で読み取れます。
- Crew Folderを追加しました。異なるWorkspaceのSessionでも共通資料・成果物を参照でき、既存WorkspaceとSession Folderは維持します。
- Additional Directoriesは各Main単位で管理し、そのMain配下のAuxiliaryと共有します。親子であっても別Mainの一覧は独立し、MCP／CLIから自身または直属子の登録・解除を扱えます。
- AuxiliaryのClose操作と専用の終了状態を廃止し、既存の会話・draftを継続できます。Sessionの削除はCrew全体を単位とし、実行・未対応相談等の削除ガードを適用します。

### Characterの相互認識

- 固定の`local-user`、Character ID、実Session／Turnを分け、別Agentからの入力をユーザー発言と混同しない情報を通常入力・保存履歴・背景Memory／Affectへ接続しました。
- 他Characterの公開情報には保存snapshotのID・名前・`description`を使います。相手のCharacter定義を自身の人格指示として取り込みません。
- Character Memoryに参加者と事実の出自を記録でき、Characterを対象とするAffectと相手別の取得を追加しました。記憶・感情の所有者と相手を分け、相手の感情や経験を推測で補いません。
- 共通promptをV7へ更新し、Agent間の依頼・相談・報告も各自のCharacter表現を保つようにしました。同僚としての距離感と操作権限は分離し、コード等の成果物の文体は従来どおり対象の規約に従います。

## 互換性・利用上の注意

- 保存先は引き続き`withmate-v6.db`、SQLiteの`user_version`は6です。起動時にCrew・queue・Coordination等のschemaを整え、既存Session・会話・Memory・Affectを継続します。Affectの対象種別追加では既存event・version・再試行情報を保持します。
- 古い受付に送信者や採用入力が記録されていない場合、現在の情報から補完せず不明・比較不能として扱います。
- 子の最終応答は自動転送しません。親の自動再開には、子がSession APIで明示報告する必要があります。`after_source_turn`の配送成立も作業成功の証明ではなく、送信元Turnの失敗・取消を区別します。
- 親子の実行設定選定や報告運用は、各Providerのユーザー管理ルールで指定します。取り込み用の[親子連携ルールサンプル](https://github.com/natumekazuki/WithMate/blob/ba1d3f8e700603a8be39f5ef6cbf9339dcaad2c8/docs/features/parent-child-session-rules.md)を用意しています。WithMateがユーザー管理ルールを自動で書き換えることはありません。
- 編集済みの背景登録指示は自動置換しません。新しい参加者・出自の標準指示を使う場合はSettingsの各用途で`Use Preset`を選択してください。
- Windows x64向け未署名NSIS installerを用意します。インストールや既存アプリの置換は自動で行いません。
- 圧縮された他Agent向け公開プロフィールの専用定義は[#935](https://github.com/natumekazuki/WithMate/issues/935)、予約Turnは[#932](https://github.com/natumekazuki/WithMate/issues/932)、Graph評価・分析用取得は[#922](https://github.com/natumekazuki/WithMate/issues/922)・[#923](https://github.com/natumekazuki/WithMate/issues/923)としてv7.1.0で扱います。本previewには含みません。
