# WithMate v7.0.1-preview.6

`v7.0.1-preview.5`から、会話の失敗と再試行の扱いを揃え、子Sessionを開かずに実行・監視できるようにしました。読み込み中と実行中の表示も見直しました。

## 会話の失敗・再試行

- Main／Auxiliaryとも、送信・実行の失敗と、アプリ再起動時に実行開始を確認できた未完了Turnを、応答側の同じ `Failed` 表示で扱います。理由は一度だけ表示し、保存済みの入力・途中の応答・Detailsを残します。Homeでは旧来の中断も `Failed` として表示します。Coordinationでは回答の配送結果と起票元Turnの失敗を区別します。
- 失敗した入力は自動で再送しません。Copilotでも送出後に受付応答が失われた場合や接続に失敗した場合、同じ入力を自動で送り直しません。再起動時は保存済みの終端を維持し、結果が不明な受付や追加入力を別のTurnに付け替えません。保存状態と実行の終了を確認した後、後続の予約は専用の手動解除なしで進みます。
- 確定した失敗Turnの `Resend` は、別のTurnの実行中でも、元の会話枠に通常の予約として追加できます。先行予約を追い越さず、実行中のTurnや現在の下書きは変更しません。再試行した入力の確認できた編集差と元の送信者名はDetailsで確認できます。受付結果を確認できないときは `Check Receipt` または `Retry Original Turn` で同じ要求IDを使います。
- 実行終了後、保存済みの応答が届くまでは表示中の本文とDetailsを同じ応答行に残し、確定した応答へ引き継ぎます。空の折りたたみ要約や履歴ナビゲーターの空のプレビューには代替文を表示せず、話者や開閉操作などは残します。

## 子Session・Monitor・承認

- MCP／配布CLIで親Agentが通常の子Sessionを作成・実行しても、Session Windowは自動で開きません。実行を開始した子はWindowがなくてもHomeと独立Monitorに表示され、利用者が明示して開けます。Windowがないまま停止したSessionは `Stopped` に残ります。承認待ちのデスクトップ通知は、対応するWindowが開いていて非フォーカスの場合が対象です。未開封の子もMonitorの `Attention` から開けます。
- 新しく通常のSession Windowを開いたときは、Mainの初期表示を `ALL` にします。同じWindowを前面に戻したり一覧が更新されたりしても、選んだ会話枠は維持します。特定の会話枠を指定した移動では、その枠を開きます。
- Copilot／OpenCodeのWithMate仲介審査では、同じ会話の承認要求を到着順に扱います。先頭が手動確認待ちなら後続の審査を始めず、先頭の解決後に条件を満たす次の要求を審査します。失効した判定を別の要求に適用しません。
- MCP／配布CLIの保存済みSessionの読み取りを、対象Sessionや要求した一覧ページに絞りました。Session Graphの更新通知も、そのCrewを表示する関係Windowに限定しました。

## 待機表示・Files・旧履歴

- 会話を読み込んでいる間はSendを送信中として表示せず、実際に送信の受付を待っている場合と区別します。継続する実行状態はHome／Monitorの静止アイコン、会話切替の静止リング、応答欄の静止した三点で示します。停止要求の受付待ちと、受付後の停止待ちも同じCancelボタンで区別します。
- Monitorの相談件数は未取得を0件として表示しません。Homeの起動準備、Session GraphのTopic本文、SettingsのApp Versionでは、待機表示を読み込んでいる対象の近くに置きました。Markdown画像の取得が長引く場合は、待機表示を画像枠の中央に置きます。
- Filesの一覧更新中はピンの追加・解除を受け付けないまま、操作ボタンのキーボードフォーカスを保持します。取得済みのAuxiliary本文を表示していれば、同じ会話の再取得中や取得失敗後も、割り当て済みの末尾移動ショートカットを使えます。
- 旧V6のTurn移行で、保存済みの応答位置を照合する際にテキスト本文とJSON形式の応答本文を区別し、一意に一致する応答の位置を復元するようにしました。
