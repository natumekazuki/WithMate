# WithMate v7.0.1

`v7.0.0`から、Mainの会話を相手ごとに読み返せるようにし、HomeにCrewの階層表示を追加しました。送信・失敗時の再送と、Providerごとの承認設定も見直しました。製品コードは `v7.0.1-preview.7` と同じです。

## 会話枠・返信・Coordination

- Mainは、新しく開くと `ALL` でそのMain自身の会話を相手で絞らずに表示します。初期枠と直属の子Sessionごとの相手枠に切り替えられ、同じウィンドウでは選んだ枠と閲覧位置を保ちます。枠の切り替えだけでは送信先を変えず、一括既読にもしません。Main／Auxiliaryの会話切替では未読と実行中を区別して表示します。
- Mainの通常送信は、明示した返信先の枠、送信時の相手枠、初期枠の順で所属を決めます。下書きの本文・添付参照・返信先は枠ごとに保持し、受付が成功した版だけを消します。保存済みの発言を選んで返信でき、引用から特定できる元発言へ戻れます。
- Session間の通常送信や直接 `Steer` は、送信元の応答内に宛先とともに表示します。同じ応答で複数の宛先へ送った順序を確認でき、カードの `@宛先` から相手枠の同じカードへ移動できます。受信側では送信元のCharacterとSessionを識別できます。
- 会話内のCoordinationの起票カードから状態を確認し、該当する相談を開けます。送信カードと起票カードはライブ表示が終わってから保存範囲の取得が完了するまで元の応答に残します。回答の配送結果と起票元Turnの失敗は区別します。
- Mainで新しい通常Turnを始めるProvider入力には `Conversation Thread` が含まれます。MCPの `session.list_messages` と配布CLIの `list-messages` は、任意の `thread` を指定して会話枠を絞り込めます。省略時は対象Sessionの全履歴を取得します。

## 送信・待機・失敗時の再送

- Main／Auxiliaryでは、受付済みの入力を予約・開始・保存まで同じ会話行に引き継ぎます。すぐ開始する送信に古い予約操作を出さず、終端直後も保存済み応答が届くまで表示中の本文・Detailsを保ちます。通常送信と直接 `Steer` で同じ下書きが重複しないようにし、停止操作は押した時点の実行・開始予約に限定します。
- 通常の失敗と、再起動時に実行開始を確認できた未完了Turnは、応答側の `Failed` 欄に理由を一度だけ表示します。保存済みの入力・途中の応答・Detailsを残し、元の要求を自動で再送しません。直接 `Steer` や受付の結果が不明なときは、成功や未送信とみなさず、照会できる場合は元の要求IDで確認します。
- 確定した失敗Turnの開始入力は、最新・過去を問わず、対応する失敗カードの `Resend` から再送できます。別のTurnの実行中でも、元の会話枠の通常予約に追加し、先行予約・現在の実行・下書きには影響しません。元のままの入力だと確認できるときは元の送信者・宛先を表示し、編集差と元の送信者名はDetailsで確認できます。
- 読み込み待ちと送信を受け付けている間、未取得と取得済みの0件を区別し、更新中も取得済みの本文・一覧・選択を保ちます。応答待機の三点、会話切替の実行リング、Monitorの実行アイコンは静止表示です。

## Home・Crew・子Session

- Homeの `Crew` タブで、Mainのウィンドウが一つでも開いているCrewを起点からたどれます。閉じている親や子も確認して開けます。Auxiliaryは所属Mainの中で選べます。Homeの初期表示と独立ウィンドウは引き続き `Monitor` です。
- `Close Descendant Windows` は、開いている子孫Mainのウィンドウだけをまとめて閉じます。実行中の会話は閉じても続きますが、端末は停止します。実行中の会話や保護対象の端末があれば、閉じる前に対象と影響を確認できます。`Delete Crew` の確認では起点Session名を表示し、削除できない場合は理由と必要な操作を示します。
- 親Agentが通常の子Sessionを作成・実行しても、Session Windowは自動で開きません。実行を開始した子はウィンドウがなくてもMonitorで確認でき、承認待ちなら `Attention` から明示的に開けます。承認のデスクトップ通知は対応するウィンドウが開いていて非フォーカスの場合が対象です。

## 承認方針と引き継ぎ

- Codex・Claude・Copilot・OpenCodeの `Approval` を `Auto Run / Auto Review / User / Safety Focused` の4択に揃えました。変更は次の送信に適用され、実行中のTurnや受付済みの予約には反映しません。Codexの `Sandbox` は別設定です。`Auto Run` はProviderの禁止ルールを上書きせず、`Safety Focused` は承認不要な操作を止めずに、実際に承認を求められた操作を拒否します。後者はOSによる隔離を追加するものではありません。
- `Auto Review` はCodex／Claudeではネイティブ審査、Copilot／OpenCodeではWithMateの仲介審査を利用します。仲介審査には保留中の操作と審査に必要な履歴を、Settingsで選んだCodexまたはClaudeに渡します。到着順で審査し、有効な本人確認の判定だけを承認画面・通知に出します。審査が未設定・利用不能、委譲できない、または有効な判定が得られない場合は不許可となり、手動へ自動では切り替えません。手動で判断する場合は `User` を選びます。旧来の `Settings Default` は共通設定が `Off` なら手動です。保存済みのProvider固有の旧制限は保持しますが、新規選択肢には含めません。
- 通常の子Sessionには、異なるProviderでも実行中の親Turnが使う共通承認方針を渡します。ただし、制限付きCodex Sandbox、選択済みCopilot Custom Agent、Provider固有の旧承認方針を異種に引き継ぐ作成は拒否します。非CodexからCodexへの子作成は `Read Only` で開始します。通常送信は受付時の宛先設定を使います。MCP／CLIの `create_child` と `enqueue` で権限設定は上書きできません。
- WithMate内で実行するOpenCodeではネイティブのサブエージェントを無効にしました。WithMateの通常の子Sessionとは別です。OpenCodeの質問では、選択した回答を会話履歴から確認できます。CodexのMCP質問フォームは不正な値で閉じず、訂正できます。

## 会話バブル・プレビュー・Files

- 返信・ブックマーク・折りたたみなどは、本文幅を削らず右上に重ねて表示します。ポインターもフォーカスもなく返信先に選ばれていないバブルでは、`Reply` だけが残りません。キーボードやホバーのない端末からも操作できます。
- 会話内HTML／PDFの `Reload` と、PDFで選択した文の `Copy Text`／`Quote` は、プレビューのヘッダーから会話バブルの返信とは別に操作できます。PDFのテキスト選択・解除でプレビュー位置を変えません。読み込みに1秒以上かかるMarkdown画像では画像枠の中央に待機表示が出ます。
- Filesの一覧を更新している間はピン操作を無効にしつつ、ボタンのキーボードフォーカスを保ちます。設定済みのAuxiliaryの末尾移動ショートカットは、同じ会話の取得済み本文が表示されていれば再取得中や取得失敗後も使えます。旧V6のTurn移行では、保存済みのテキスト本文またはJSON内の応答本文が一意に一致する場合に、応答の位置を復元します。
