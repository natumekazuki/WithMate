# WithMate v7.0.1-preview.4

`v7.0.1-preview.3`から、HomeでCrewの階層をたどれるようにし、Mainの会話枠ごとの表示と入力を整理しました。

## HomeのCrewとウィンドウ操作

- Homeに `Crew` タブを追加しました。Mainのウィンドウが一つでも開いているCrewを最上位のMainからたどり、閉じている親や子も確認できます。Homeの共通検索ではMainのタイトルやCharacter名で絞り込めます。Main行からウィンドウを開くか前面に出せます。AuxiliaryはMainの子階層とは別に展開し、所属するMainのウィンドウ内で選べます。Homeの初期表示と独立ウィンドウは引き続き `Monitor` です。
- Main行のメニューから対象の `Close` と、開いている子孫Mainのウィンドウだけをまとめて閉じる `Close Descendant Windows` を使えます。一括操作で本人や兄弟のウィンドウは閉じません。実行中の会話はウィンドウを閉じても継続し、端末は停止します。実行中の会話や保護対象の端末がある場合は、閉じる前に一度だけ対象と影響を表示して確認します。

## Mainの会話枠

- Mainの画面から通常送信した入力とその応答は、明示的に返信した発言の枠を優先し、返信先がなければ送信時の相手枠、相手枠もなければ初期枠に表示されます。送信後に閲覧枠を切り替えても移らず、`ALL` では元の順序で一度だけ表示されます。送信先や実行先は変わりません。保存済みの履歴は書き換えず、旧版の送信は保存済みの返信参照から確かめられる場合にだけ所属を反映します。
- 本文・添付参照・明示返信の下書きを、同じウィンドウ内の `ALL`・初期枠・相手枠ごとに保持します。受付が成功しても送信した版だけを消し、送信後の追編集や受付に失敗した下書きは残ります。Mainの会話切替に出る実行中のリングは、このMainが実行しているTurnの所属枠だけに表示します。`ALL` や予約待ちだけの場合、子だけが実行中の場合には表示しません。
- Mainで新しい通常Turnを始めるProvider入力に `Conversation Thread` を追加しました。実行中のTurnへの `Steer` では所属を変更しません。MCPの `session.list_messages` と配布CLIの `list-messages` では、任意の `thread` で同じ会話枠の保存本文を取得できます。初期枠は `null`、相手枠は該当する子Mainの識別情報を指定し、省略時は従来どおり対象の全履歴を取得します。
