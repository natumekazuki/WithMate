# WithMate v7.0.0

- Version: `7.0.0`
- Tag: `v7.0.0`（正式公開時に付与）
- 公開元: `master`（PR・CI確認と統合後に公開）
- 配布形式: Windows x64向け未署名NSIS installer

Roleを持つSession同士が依頼・相談・報告をやり取りし、同じCrewで資料と作業の判断を共有できる正式版です。前の正式版`v6.5.0`から、`v7.0.0-preview.8`までの変更をまとめています。

**v6.5.0などMemory／Affectを持つ版から更新すると、初回起動時に専用データを退避なしで破棄します。** 更新前に、下の「互換性・移行」を確認してください。

## 変更内容

### Session同士の非同期協同

- Standalone・全体統括・個別統括・Worker・Auxiliaryを識別し、同じ起点の通常Sessionと各AuxiliaryをCrewとして扱います。親はWorkspace、Provider、Model、Depth、実行権限を指定して通常子Sessionを作成できます。
- 実際の直属親子間で依頼・追加指示・報告を送れます。受理済みの仕事は送信元のTurn終了後も継続し、明示報告を受けた親は、追加のユーザーSendなしで次のTurnを開始できます。子の最終応答だけを自動転送する仕組みではありません。
- 即時配送と、送信元Turnの終了・結果保存後に処理を始める`after_source_turn`を選べます。後者の待機中でも、別の即時入力を処理できます。配送成立と作業成功は区別します。
- GUIとMCP／CLIの入力を共通の永続queueで扱います。GUIでは待機中の本文・添付の編集と並べ替えができ、保存済みの受付・採用入力・実行設定・結果を照合できます。
- 通常の親子送信ごとにModel・Depth・実行権限を指定できます。受理時に採用した設定を次のTurnへ渡し、Sessionの既定値や実行中Turnの設定は変更しません。子から親への報告で省略したModel・Depthは、親のDefaultを含む保存値を引き継ぎます。
- 親から直属の通常Codex子の実行中Turnへ、Sessionと世代・WithMate Turn IDを指定してSteerできます。実行中設定は維持し、適用できない場合に別Turnへ自動転送しません。
- 共通Session MCPをCodex・Copilot・Claude Agent・OpenCodeへ接続しました。Windows配布物には`withmate-session.cmd`を追加し、MCPとCLIから同じSession操作を利用できます。

### 相談と保存結果の確認

- Coordinationで作業上の相談を起票し、呼び出し元への相談、ユーザーへの引継ぎ、回答配送、取り下げ・訂正を扱えます。Provider自身の質問・承認とは別の機能です。
- Monitorの専用枠とSession右ペインから相談を選び、本文・回答を確認して対応できます。回答の取得済み・利用済み・相談解決を区別し、取り下げても受理済み回答は消しません。
- 相談・回答の受信会話には、内部通知JSONではなく送信者の自然文を表示します。古いpreviewの保存済み通知も、原文を書き換えず自然文として表示できます。
- 保存済みの会話、受付・Turn、応答、操作、成果物を、仕事を再実行せず参照できます。自Crewを既定に、別Crew・全Crewの公開情報も明示して読み取れます。読取可能であることは送信・変更の許可ではありません。
- 送受信者・宛先・Steerの発言者を保存された来歴から表示し、送信側の相対ファイルリンクとローカル画像を送信元の参照先へ接続します。入力原文・採用入力・実行設定は応答のDetailsで確認できます。

### Crewの共有と継続

- Crew内の通常SessionとAuxiliaryは、初回接続から同じSession Graphを参照・更新します。別CrewのGraphは明示指定で読み取れます。
- Crew Folderで、異なるWorkspaceのSession間でも資料を共有できます。WorkspaceとSession Folderは引き続き利用できます。
- Additional DirectoriesはMainごとに管理し、そのMain配下のAuxiliaryと共有します。別Mainの一覧は親子でも独立し、MCP／CLIから自身または直属子の登録・解除を扱えます。解除は実体Directoryの削除ではありません。
- AuxiliaryのClose操作と専用の終了状態を廃止し、会話とdraftを継続できます。Sessionの削除はCrew全体を単位とし、実行中・未対応相談等のガードを適用します。
- Agent作成の子WindowとRestore SessionsのWindowは最小化で用意します。復元途中の未処理対象の消失と、初期読込失敗後に復元できなくなる問題を修正しました。
- 通常の`File → Exit`で終了処理が反復し、プロセスとデータディレクトリのロックが残る問題を修正しました（[#952](https://github.com/natumekazuki/WithMate/issues/952)）。

### 実行方針とCharacterの文脈

- Provider／Modelの選定基準、Depth・Approval・Sandboxの目安、契約経路の利用条件と、Git Worktreeの端末共通ルート・repository別配置ルールをMCP／CLIから取得・管理できます。設定は判断材料であり、照会だけでGit操作やProvider切替は行いません。Provider quotaは保存済みの取得状態・日時・値を読取専用で確認できます。
- Codex子Sessionの作成時にReviewerを選べます。catalogで対応候補を確認し、`on-request`と`auto-review`の組合せも指定できます。省略時は従来どおり`user`です。
- 固定のユーザー参照、Character ID、実Session／Turnを分け、他Agentの入力を人間ユーザーの発言と混同しない来歴を渡します。他Characterの公開情報にはID・名前・descriptionを使い、相手のCharacter定義を自身の人格指示として取り込みません。
- Session metadataのTitleは目的・主題・担当対象、Descriptionは担当範囲・現在状況として取得・更新できます。現在値と常時保守指示はpromptへ注入しません。
- 固定promptを必要な文脈へ絞りました。日時はTurn開始時のUTC offset付き現在日時とし、Settingsの`Current Date`でON／OFFを選べます。従来の日時設定を引き継ぎ、会話のTiming集計とTool Call Presenceの固定指示・設定は廃止しました。

## 互換性・移行

### Memory／Affectの廃止と専用データの破棄

- 一般Memory、Character Memory／episode、Character Affectを廃止しました。専用画面・設定・MCP／CLI、背景実行、Character context／Affect投影・afterglow、専用履歴・診断、暗号化添付管理も廃止対象です。
- **v6.5.0やv7.0.0-preview.6以前からの更新では、初回起動時に専用テーブルの記録・関連情報、専用設定、管理対象の暗号化添付・keyringを退避なしで破棄します。** 破棄したデータを旧データから再取込・再生成しません。preview.7以降で既にこの移行が済んでいる場合も、廃止された機能は戻りません。
- 通常Session／Auxiliary、会話・操作履歴、Character定義・資産、実行管理のTurn時刻、保存された来歴、Session Graph、Repository Glossary、プロジェクト情報、共有DB・ファイルは保持します。V4元DB、元の取込ファイル、利用者のexportは破棄対象外です。
- 専用ファイル削除とSQL更新は、一括で成功・取消される処理ではありません。途中で失敗すると起動を中止し、SQL更新をロールバックして次回起動で残りを再試行しますが、削除済みファイルは戻りません。**旧版のコードへ戻しても、破棄済みの記録・添付は復旧できません。**
- 過去の経験・判断の能動想起、episodeの継続、Affectの保存・時間減衰は利用できなくなります。Character表現は定義と現在の会話文脈に依存します。通常履歴・Graph・Glossaryは残りますが、Memory／Affectと同じ体験を代替するものではありません。
- 廃止したMCP／CLIに互換入口はありません。外部管理の指示・設定に旧入口への参照がある場合は見直してください。WithMateは製品外のルール・Skills・Character packや既設shim／aliasを自動で書き換え・清掃しません。

### Session連携と設定

- 保存先は引き続き`withmate-v6.db`、SQLiteの`user_version`は6です。起動時にCrew・queue・Coordination等のschemaを整えます。古い受付にない送信者・採用入力は、現在の情報から補完せず不明として扱います。
- 親から子への通常送信ではModel・Depthを明示します。Depthなしは空文字列です。実行権限は全ProviderでApproval、CodexではSandboxも明示します。独自の呼出側は新しいSession MCP／CLI schemaへ合わせてください。
- 選定方針・Worktree配置ルールは初期状態では未設定です。恒久設定の変更はユーザーの明示指示に従います。配置解決は照会であり、Worktreeを作成・削除しません。
- 親子の担当選定・報告運用は各Providerのユーザー管理ルールで指定します。ルールを自動で書き換えることはありません。運用例は下の固定版ガイドを参照してください。

## 検証結果

- V7の各preview段階で、変更範囲の自動テスト・型検査・依存境界checkを実施しました。Session受付・保存・配送、Coordination、MCP／CLI、移行時の専用データ破棄と通常データ保持・失敗時の再試行を確認しています。
- 分離した開発アプリの実Codex親子で、依頼→相談→回答→子の取得・報告→親の自動再開を確認しました。Windowsソース版の合成データでは、通常Exitによる終了・ロック解放と、同じprofileからのWindow集合・履歴・Auxiliary draftの復元を確認しました。
- preview.8のWindows x64配布ビルドと同梱内容・CLI・native依存の確認が成功しました。その最新版をインストールしたユーザーから、一通りの検証完了と正式版へ進む受入を得ています。
- `7.0.0`のrenderer・PDF reader・Main・CLI buildと配布設定の関連6 testsが成功しました。正式版の配布物は、master統合後の公開対象commitから作成します。
