# WithMate v6.3.29-preview.10

対象タグ: `v6.3.29-preview.10`

v6.3.29-preview.9以降の統合済み変更をまとめたソースプレビューです。Windows installerはlocal生成のみで、配布やGitHub Release作成は含みません。

## 主な変更

- Codexを公式CLIのApp Server接続へ移行しました。Main／Auxiliaryの現在turnへComposerの `Send Input` と送信shortcutから追加入力でき、Providerからの質問には既存formで選択肢・自由記述を回答できます。secret欄はpassword inputとして表示します（[#780](https://github.com/natumekazuki/WithMate/issues/780)）。
- Codexの追加入力では、一致する受付ACKを確認した入力だけを消費・監査保存します。受付待機中の新しい編集、終了・取消とACKの競合、拒否後のAuxiliary draft保存と明示再送を扱い、追加入力を新規turnへ黙って振り替えません。
- Main／Auxiliaryの会話本文は最新60件から表示し、前後のページを必要時に取得するようになりました。FindとBookmark navigatorは全履歴を対象にし、移動先の本文を取得します。非表示Auxiliaryの本文保持量を抑え、確定した検索本文の投影を再利用します。連続した検索・履歴移動では最後の選択を維持します（[#781](https://github.com/natumekazuki/WithMate/issues/781)、[#737](https://github.com/natumekazuki/WithMate/issues/737)）。
- Copilotの取消時に、開始準備・停止確認・後片付けの完了まで次の送信を止め、終了済みsignalでProvider turnを開始しないよう修正しました。Home／Monitorも取消終了待ちを実行中として扱い、停止確認前にStoppedへ切り替えません（[#782](https://github.com/natumekazuki/WithMate/issues/782)、[#783](https://github.com/natumekazuki/WithMate/issues/783)）。
- Session title保存後の一覧・通知投影の失敗を、保存自体の失敗と分離しました。保存済みtitleを古い値へ戻したり、失敗した通知を理由に重複保存したりしないようにしています（[#738](https://github.com/natumekazuki/WithMate/issues/738)）。
- Windowsの内蔵TerminalはPowerShell 7を優先し、見つからない場合だけWindows PowerShell 5系を使います。現在ドライブに依存する探索pathは除外し、検出済み7の起動失敗を5系へ自動切替しません（[#779](https://github.com/natumekazuki/WithMate/issues/779)）。
- Filesヘッダーの操作を最小幅でも1行に収め、Files側のFile Preview操作ownerを整理しました。Memoryの文書を現行契約へ整理し、Home／送信／診断などのtest検出力を補強しました（[#778](https://github.com/natumekazuki/WithMate/issues/778)、[#730](https://github.com/natumekazuki/WithMate/issues/730)、[#728](https://github.com/natumekazuki/WithMate/issues/728)、[#731](https://github.com/natumekazuki/WithMate/issues/731)、[#732](https://github.com/natumekazuki/WithMate/issues/732)）。

## 互換性と利用上の注意

- Codex CLIは `0.159.0` に固定し、TypeScript SDKを経由せずApp Serverを直接起動します。既存の認証・実行設定・保存threadの継続経路を使用し、失敗時の別Provider・別モデル・新threadへの暗黙切替は行いません。App Serverの入力質問はexperimental APIです。
- Codexの受信済みterminal通知は後続EOFでも保持します。cleanup失敗はnativeの完了・失敗・中断を上書きせず、独立した診断として記録します。所有processの終了確認までは同一Session／workspace／threadでの再実行を止めます。
- WindowsのCodex process ownershipは、同梱した `koffi` とJob Object、Node-mode supervisorを使用します。所有権の取得・割当てに失敗した場合は起動を失敗させ、非所有processへのfallbackは行いません。
- 会話のページ取得は保存履歴の削除ではありません。取得失敗時は読み込んだ本文とComposerを保持し、対象会話でRetryできます。履歴とProvider threadを作り直すためのmigrationは追加していません。
- preview.9までの注意点は[前回のリリースノート](v6.3.29-preview.9.md)を参照してください。今回の詳細は統合commitに固定した[Provider Adapter](https://github.com/natumekazuki/WithMate/blob/aa128a4a06e56d90b18583c392f117b6bf3ffa39/docs/design/provider-adapter.md)、[Desktop UI](https://github.com/natumekazuki/WithMate/blob/aa128a4a06e56d90b18583c392f117b6bf3ffa39/docs/design/desktop-ui.md)、[会話読込](https://github.com/natumekazuki/WithMate/blob/aa128a4a06e56d90b18583c392f117b6bf3ffa39/docs/features/long-session-performance.md)、[配布構成](https://github.com/natumekazuki/WithMate/blob/aa128a4a06e56d90b18583c392f117b6bf3ffa39/docs/design/distribution-packaging.md)に対応します。
