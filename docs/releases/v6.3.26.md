# WithMate v6.3.26

v6.3.26は、v6.3.25以降に追加・変更された機能をまとめたリリースです。Codex Sessionの実行速度とReviewerを選択できるようにし、File Explorerのパス操作、Provider共通のMemory MCP、Character authoringのKernel設計を追加しました。Changes、Git履歴、Windows通知、Session復元などの操作性と信頼性も改善しています。

## 主な追加機能

### CodexのFast modeとAuto-review

- Codex SessionのAction Dockに`Speed`を追加し、`Standard`と`Fast`をSessionごとに選択できるようにしました。
- 選択した速度をturnごとのCodex実行へ反映し、既存threadを可能な限り継続するようにしました。
- `Reviewer`を追加し、承認の判定主体を`User`と`Auto-review`から選択できるようにしました。
- `Reviewer`はApprovalが`never`の場合、実行中、または読み取り専用Sessionでは現在値を保持したまま変更できません。
- Main、Companion、Auxiliary Sessionで選択値を保存し、新しいAuxiliary Sessionには既定の継承規則を適用します。

詳細は[Desktop UI](../design/desktop-ui.md)を参照してください。

### File Explorerのパス操作

- File Explorerのroot、directory、fileの右クリックメニューに`パスをコピー`と`パスを挿入`を追加しました。
- `パスを挿入`は、Workspace内の対象を相対パス、Workspace外の対象を絶対パスとしてcomposerへ挿入します。
- Windowsのfile rowでは、既存の`ファイルをコピー`も同じメニューから利用できます。
- メニュー表示後にSession、認可root、composerの状態が変わった場合は、古い操作結果を現在のSessionへ反映しないようにしました。

詳細は[Desktop UI](../design/desktop-ui.md)を参照してください。

### Provider共通のMemory MCP

- Memoryの通常操作をProviderごとのmanaged Skillから切り離し、Provider共通MCPの`tools/list`をagent向け契約の正本にしました。
- Memory targetを現在のSessionとCharacterから解決するactor-relative形式へ変更し、callerがuserやCharacterのidentityを指定する経路を廃止しました。
- MemoryとCharacterの変更操作を現在のlogical turnへ束縛し、期限切れのcapabilityや別Sessionの権限をdispatch前に拒否するようにしました。
- MCP transport障害時のCLI fallbackは、MCP側が許可した同一operationだけを引き継ぎ、operator権限へ昇格しないようにしました。
- SettingsのMemory diagnosticsをruntime、CLI shim、直近errorのread-only表示へ整理し、credential、binding、個人path、Memory本文を表示しないようにしました。
- `withmate-memory` CLIの配布元をSkill catalog外の共通artifactへ移し、Provider directoryに残る既存Skillを自動変更しないようにしました。

詳細は[ADR 024](../adr/024-provider-common-memory-mcp-boundary.md)を参照してください。運用手順は[Memory Affect MCP Runbook](../runbooks/memory-affect-mcp.md)に記載しています。

### Character authoringのKernel設計

- 新規作成とfull authoringで、Characterらしさを「選択の核」「言語アイデンティティ」「状態変調」の三層から設計するようにしました。
- 注意、評価、対人目的、感情、判断、voiceを生成規則として記述し、完成返答の台詞集へ依存しない構成へ更新しました。
- source observation、採否、不確実性、revision guardrail、validation結果を`character-notes.md`へ分離するようにしました。
- Name-swap、Phrase-suppression、未知場面、長文維持、relationshipなどの検証観点を追加しました。
- targeted updateでは既存の有用なidentityとsection構成を維持し、旧Characterの自動migrationや一括rewriteは行いません。

詳細は[Character Definition Format](../design/character-definition-format.md)と[ADR 011](../adr/011-character-authoring-kernel.md)を参照してください。

## 表示と操作の変更

### ChangesとGit履歴

- `Changes`タブは認可済みGit repositoryの枠だけを先に表示し、`Refresh`を押すまで差分を取得しないようにしました。
- 複数repositoryの更新を同時2件まで並行実行し、完了したrepositoryから表示するようにしました。
- 再度`Refresh`した場合は未開始の古い要求を破棄し、実行中の取得後に最新の要求だけを続行します。
- `Files`、`Changes`、`History`を切り替えても、展開状態、選択、取得済みの差分をWindow内で保持するようにしました。
- Git履歴にHEAD、branch、tagのbadgeを追加し、文字markerとlabelでも種類を区別できるようにしました。
- commit差分の生成でも対象worktreeのGit改行設定を使用し、設定差によってfile全体が変更扱いになる表示を防ぎました。

詳細は[File root単位のGit Changes](../adr/015-file-root-scoped-git-changes.md)と[Git履歴とcommit preview](../features/git-history-and-commit-preview.md)を参照してください。

### Session interface

- 長いmessageの縮小・展開buttonが本文領域だけへ追従し、Detailsやartifactの上に重ならないようにしました。
- Session復元に成功した場合の通常feedbackを省き、復元できなかったSessionと理由だけを表示するようにしました。
- CodexのApprovalから廃止済みの`on-failure`を削除し、保存済みの旧値は既定の`untrusted`として扱うようにしました。

詳細は[Messageの縮小表示とnavigator](../features/session-message-collapse-and-navigation.md)と[Session Windowの復元](../features/session-window-restore.md)を参照してください。

### Windows通知

- Sessionのturnが非cancelのerrorで終了した場合も、対象Windowが前面にない時にWindows通知を表示するようにしました。
- error通知にはassistant responseやprovider errorの詳細を含めず、Session名と失敗したことだけを表示します。
- 利用者によるcancelと、Sessionを保存しないsetup failureでは通知しません。

詳細は[ADR 006](../adr/006-windows-session-turn-notifications.md)を参照してください。

## 互換性と移行

- application dataの利用者向け手動migrationはありません。
- Codexの保存済みApprovalが`on-failure`の場合は既定の`untrusted`へ正規化されます。
- agent向けMemory MCPのtarget schemaはactor-relative形式へ変更されました。旧request shapeとのcompatibility fallbackはありません。
- Provider directoryへ過去のWithMateが配置した`withmate-memory` Skillは、自動削除や自動更新を行いません。
- 既存Characterのstorage形式と8,000文字制約は維持され、Kernel構成への手動migrationは不要です。
