# WithMate v7.0.1-preview.7

`v7.0.1-preview.6`から、送信・予約から保存済み履歴へ切り替わるときの会話表示を見直し、失敗した入力の再送と自動審査から本人に確認する条件を明確にしました。

## 送信・予約・会話履歴

- Main／Auxiliaryでは、受付済みの入力を予約・実行開始・保存まで同じ会話行で更新します。予約からの `Steer` も同じ行に引き継ぎ、予約の編集内容を反映します。別のTurnが始まっても、閲覧中の応答のDetails・フォーカス・表示位置を維持します。未開始の予約の取消と、実行済み入力や途中の応答の保存を区別します。
- 応答に付く送信カードとCoordinationの起票カードは、ライブ表示が終了してから対応する保存履歴が届くまで、元の応答に残します。履歴をまだ読み込んでいないことをカードの削除とは見なしません。
- 同じ会話で通常のSendまたはComposerからの直接 `Steer` を受け付けている間は、同じ下書きをもう一方から重ねて送信しません。直接 `Steer` の結果を確認できないまま対象Turnが終わった場合は、履歴上も結果不明として扱い、自動で再送しません。
- 応答欄の待機を表す三点は、実行の開始前・実行中・保存済み応答の読み込み中のいずれも静止表示に揃えました。Composerで送信の受付を待つ短いスピナーとは別の表示です。

## 会話バブルと埋め込みプレビュー

- 返信・ブックマーク・折りたたみなどの操作を、本文の幅を削らず右上に重ねる従来の配置に戻しました。マウス操作では、返信先に選んでいないバブルからポインターとキーボードフォーカスが外れると、`Reply` だけが残ることはありません。バブルにポインターを置いたとき、キーボードで操作するとき、返信先として選択しているときは操作が表示されます。ホバーがない端末でも操作できます。
- 会話内に埋め込んだHTML／PDFでは、`Reload` と、PDFの選択時に使う `Copy Text`／`Quote` をプレビューのヘッダー内にまとめました。会話バブルの `Reply` とは別の位置にあり、それぞれ直接押せます。

## 失敗した入力の再送

- 失敗が確定したTurnは、最新・過去を問わず、対応する失敗カードの `Resend` から保存済みの開始入力を再送できます。失敗の回復操作に `Edit` は出しません。内容を変える場合は、新しい入力として送信します。対応する失敗Turnがない旧来の中断や取消の回復操作は、引き続きAction Dockで使えます。
- 元の入力も再送入力も変更されていないと確認できる場合は、予約・実行中・保存済みのカードに元の送信者と宛先を示し、照合できた送信者のCharacterカラーを使います。編集差と元の送信者名はDetailsで確認できます。

## Copilot／OpenCodeの承認

- `Auto Review` では、会話ごとに承認要求を到着順で審査します。審査中や順番待ちの要求は手動確認に出さず、先頭の審査が有効な `ask_user` を返したときだけ確認・通知の対象にします。後続の要求が追加・取り消されただけでは、先頭の審査をやり直しません。
- 審査が未設定・利用不能、操作が審査に委譲できない、または有効な判定が得られない場合は、手動確認へ切り替えず不許可とします。手動で判断する場合は `User` を選びます。旧来の `Settings Default` は共通設定が `Off` なら引き続き手動です。Codex／Claudeのネイティブ審査はこの変更の対象外です。

## Crewの削除確認

- `Delete Crew` の確認には起点Sessionの名前と `Cancel`／`Delete Crew` を表示します。削除できない場合は理由と、必要に応じてCoordinationを開く操作を表示します。
