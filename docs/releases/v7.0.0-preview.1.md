# WithMate v7.0.0-preview.1

- Version: `7.0.0-preview.1`
- Tag: `v7.0.0-preview.1`
- 公開元: `feat/v7.0.0`

親子Session間の依頼ごとに実行設定を指定できるようにし、親から直属の子の実行中Turnへ明示的にSteerする操作を追加したpreviewです。`v7.0.0-preview.0`からの変更を収録します。

## 変更内容

- MCP／CLIの通常の親子送信で、Model・Depth・実行権限を送信ごとに指定できます。受理時に採用した設定を固定し、次のTurnへ渡します。Sessionの既定値や実行中Turnの設定は変更しません（[#936](https://github.com/natumekazuki/WithMate/issues/936)）。
- `session.steer`／`withmate-session steer`で、親Agentから直属の通常子Sessionの実行中Codex Turnへ追加指示を送れます。`session.get`の`currentTurn`からWithMateのTurn IDを取得し、対象Sessionの世代とTurnを明示して操作します（[#938](https://github.com/natumekazuki/WithMate/issues/938)）。
- Steerは実行中TurnのModel・Depth・権限を維持します。別Turnやqueue受付を作らず、追加入力と親の来歴を保存します。保存済み実行入力の`inputOrigin`と履歴の発話主体から送信元を確認できます。
- 対象Turnの終了・世代不一致・非対応ProviderではSteerを適用しません。Providerへの送信後に結果が確定できなければ`SESSION_STEER_UNKNOWN`として返し、通常送信・別Turnへの自動転送や自動再試行は行いません。

## 互換性・利用上の注意

- 親から子への通常送信ではModel・Depthを明示します。Depthなしは空文字列で指定します。子から親への報告では各項目の省略時に親の保存値を採用します。実行権限は全Providerで承認方針、Codexではsandboxも明示してください。既存の呼出側は新しい送信schemaに合わせる必要があります。
- 受理済みの旧queue受付・実行結果を保持します。今回、新しいDB tableやmigrationは追加しません。古い保存入力にない送信元情報を現在の情報から補完することもありません。
- Steerは実直属親から通常子への操作に限定します。子から親、兄弟間、孫への直接送信、Auxiliaryへの操作には使えません。通常の報告とCoordinationは従来のqueue配送を継続します。
- Agent向けの[親子連携ルールサンプル](https://github.com/natumekazuki/WithMate/blob/531befd3baf72d25128c149604c3692d355a922b/docs/features/parent-child-session-rules.md)を更新しました。ユーザー管理のルールは自動で書き換えません。
- Windows x64向け未署名NSIS installerを用意します。インストールや既存アプリの置換は自動で行いません。

## 検証結果

- 実装commit `531befd3baf72d25128c149604c3692d355a922b`で、関連10ファイルの110 test、production・script・testの型検査、SQLite owner・依存境界check、Main・CLI buildが成功しました。変更testの独立レビューにブロッカーはありません。
- Steerの検証は実Storage Workerを使用し、Provider・HTTP交換・currentTurn解決はfixtureです。実ProviderへのSteer送信確認とは区別します。
- `7.0.0-preview.1`のrenderer・PDF reader・Main・CLI buildとWindows NSIS生成が成功しました。installerは683,193,794 bytes、blockmapは713,625 bytesです。既存のchunk size警告があります。
- 同梱5 CLIのhelpとSession CLIのSteer schema、4 Provider binaryの配置を確認しました。packaged Electron 44.10.1のNode modeで`node-pty`・`koffi`のnative load、ASAR内の版番号とMain／renderer入口を確認しました。配布設定・Memory配布境界の対象test 3件も成功しました。
- release準備の変更は版番号とノートだけです。新installerのインストール・GUI起動は今回の確認には含みません。
