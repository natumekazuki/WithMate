# WithMate v6.5.0-preview.2

- Version: `6.5.0-preview.2`
- Tag: `v6.5.0-preview.2`
- 公開元: `feat/v6.5.0`

`v6.5.0-preview.1`の利用中に確認した、Memory・Character Affectの参照と入力診断、背景処理の結果記録を修正したプレビューです。ソースをbranchとtagで公開します。

## 変更内容

### MemoryのProject解決とAuxiliaryの参照

許可された未登録Projectの解決失敗によって、同時に要求した別targetのMemory読取まで拒否される問題を修正しました。認可と解決を対象ごとに行い、未登録Projectへの初回保存も適切なProjectへ結び付けます。許可外targetを黙って省く部分成功にはしません。

通常AuxiliaryのCharacter context・Affect参照で、実際のAuxiliaryと親の情報を保持するようにしました。Mainとしての誤解決や、同名のMainへの誤参照を防ぎます。

### 背景Affectの参照と根拠指定

背景Affectから、元会話のCharacter・Sessionに対する`character_affect.inspect`を利用できます。訂正・resetや別Characterへの権限は追加していません。

背景Affectの候補に、根拠となる保存済みmessageの`sourceMessageSeq`を指定できます。アプリが対応する終端Turnと時刻へ解決するため、AIがTurn IDを組み立てる必要がありません。`sourceTurnId`による直接指定も維持します。両方の指定、参照なし、許可範囲外・未完了Turnへの参照は拒否し、近傍や最新Turnへ代用しません。

### 背景実行の終了状態と操作診断

Agentの実行終了状態と、個々のtool操作の成否・保存効果を分離しました。操作拒否があってもAgentが正常終了した場合は`completed`と操作診断を併記し、先行する操作拒否で実行全体を`failed`へ上書きしません。

操作拒否・失敗・結果不明は専用ログに残し、次回の継続材料にも渡します。正常終了を全件保存成功へ読み替えず、先行して保存された項目を巻き戻したり、実行全体を自動再送したりしません。

### 入力エラーの識別

Memory・Characterの公開入力schemaでの拒否を、MCPとCLI共通の`WITHMATE_MEMORY_INVALID_INPUT`へ整理しました。対象toolとfieldの位置、検証code、期待型・範囲・選択肢・余剰fieldを返します。

Character episodeのような代替条件も、unionの候補ごとの不足条件まで確認できます。例えば「観測事実またはCharacterの観察が必要」と「本文がない」を区別し、入力を修正できます。入力値全体、secret、stackはエラーへ含めません。公開入力の拒否はruntimeへの保存前に行い、`effect: none`を返します。

## 互換性・利用上の注意

- 公開済みの単件・一括Memory登録、`sourceTurnId`指定、保存済みMemory・Affectのデータ形式を維持します。新しいDB migrationや既存データの手動修復はありません。
- 保存済みの背景登録指示は自動で書き換えません。
- `completed`はAgent実行の正常終了を示し、全操作の成功や全件保存の証明ではありません。操作結果と保存効果を確認してください。
- 背景の診断は引き続き`userData/logs/background-failures.jsonl`へ記録します。過去のログや保存済みの結果は書き換えません。
- 公開はソース・tag・repository内ノートです。Windows x64向けの未署名NSIS installerもローカルに作成しましたが、外部への配布物アップロードは行っていません。
