# WithMate Auto Review

## 設定と適用範囲

Settings の `WithMate Auto Review` で `Review Provider`、`Review Model`、対応する場合は `Review Depth` を選び、保存すると有効になる。既定は `Off`。審査役はネイティブAuto Reviewと構造化出力を使えるClaudeまたはCodexで、選択先の通常の認証・利用枠を使用する。現在の選択が使えなければ既存の手動承認を使い、別モデル・別Providerへ切り替えない。

Copilot／OpenCode の `Provider Controlled` で実際に発生した承認要求が対象。CopilotでProviderが本人の判断を要求する場合は手動承認を維持する。Codex／Claude のネイティブ審査、各ProviderのSandbox・既定権限、通常親子の実行条件の継承・捕捉は変わらない。通常Session MCP／CLIはApproval・Sandbox・Reviewerの指定を引き続き受け付けない。

## 審査会話と履歴の境界

要求元の WithMate 実行Turnで、最初に審査できる実要求が来た時だけ審査会話を開く。後続は同じ会話に今回の操作を渡す。Turnをまたがず、Turn終了・取消で審査会話を閉じる。Session接続は元Turnの通常の認証・失効に従う。通常のCrew子、審査会話の永続化、履歴のコピーは作らない。

審査の入力は実際の保留操作（Providerの引数・対象、既存要求から分かる影響）と要求元Session・世代・WithMate Turn。最初は本人の依頼、委譲経路、追加入力を調べ、後続では本人による元／親Sessionの新しい指示・訂正・撤回を読み、今回の操作に照らす。どの指示がこの操作を許すかの意味判断は審査役に委ねる。

審査役はClaude Code SDKまたはCodex App Serverの通常経路で起動し、組み込み指示で審査だけを担当させる。元の保留操作を審査するのはWithMateだが、審査役自身が行う操作の承認はClaudeの`auto`、またはCodexの`on-request`／`auto_review`に委ねる。WithMateは審査役の操作を承認しない。履歴は元Turnとして既存の認証済みSession APIから取得する。その起点は読取先の上限ではなく、通常のアクセス規則が適用される。実操作と取得した保存済み会話は選択した審査Providerへ送信され、機微な情報を含み得る。認証情報は通常の接続設定に渡し、審査プロンプトやWithMateの保存ログには含めない。

## 一件の判定と手動承認

組み込みの審査指示は、保留操作を実行せず、Session Graphの確認・記録など通常開発の定例手順を行わずに、必要な履歴だけを読むよう審査役に求める。本人の最新依頼の通常手順や現行の許可範囲に対象・引数・影響が収まる場合は一件だけ許可し、指示に反する場合は拒否する。範囲外・不明の場合は本人に確認する。

審査結果はアダプターの構造化チャネルから得た `decision: allow_once | deny | ask_user` と短い `reason` のみ。操作が欠ける、履歴を読めない、判断が曖昧、結果が不正、審査役が本人確認を要する、通信失敗、タイムアウトなどの場合は従来の承認を残す。自然文は許可の根拠にしない。

自動適用できるのは同じ保留要求の先頭一件だけ。ユーザーの手動解決、元操作・Turnの取消／終了、並行する承認要求、審査中のGUI入力や設定変更が先に確認された場合は、古い判定を適用しない。入力変更は経路をWithMateが分類せず、審査中に受け付けたGUI入力を保守的に扱う。手動操作は審査中も可能で、次の要求に使い回すのは会話の文脈だけである。
