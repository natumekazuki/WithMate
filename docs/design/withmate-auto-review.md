# WithMate Auto Review

## 設定と適用範囲

Settings の `WithMate Auto Review` で `Review Provider`、`Review Model`、対応する場合は `Review Depth` を選び、保存すると有効になる。既定は `Off`。選べる審査Providerは、履歴読取だけに隔離した会話と構造化出力の両方に対応するアダプターに限る。現在は Claude が対応し、Claude Code の認証・利用枠を使用する。現在の選択が使えなければ既存の手動承認を使い、別モデル・別Providerへ切り替えない。

Copilot／OpenCode の `Provider Controlled` で実際に発生した承認要求が対象。CopilotでProviderが本人の判断を要求する場合は手動承認を維持する。Codex／Claude のネイティブ審査、各ProviderのSandbox・既定権限、通常親子の実行条件の継承・捕捉は変わらない。通常Session MCP／CLIはApproval・Sandbox・Reviewerの指定を引き続き受け付けない。

## 審査会話と履歴の境界

要求元の WithMate 実行Turnで、最初に審査できる実要求が来た時だけ審査会話を開く。後続は同じ会話に今回の操作を渡す。Turnをまたがず、Turn終了・取消では審査会話を閉じ、履歴資格を失効させる。通常のCrew子、審査会話の永続化、履歴のコピーは作らない。

審査の入力は実際の保留操作（Providerの引数・対象、既存要求から分かる影響）と要求元Session・世代・WithMate Turn。最初は本人の依頼、委譲経路、追加入力を調べ、後続では本人による元／親Sessionの新しい指示・訂正・撤回を読み、今回の操作に照らす。どの指示がこの操作を許すかの意味判断は審査役に委ねる。

審査役にはManaged MCPの履歴専用資格を発行する。ホストだけが有効な元Turnの通常bindingを保持し、既存のSession履歴読取へ取り次ぐ。履歴資格は他のMCP endpointや通常のCLI権限を持たず、送信・Session更新・任意shell等のツールを審査会話へ登録しない。履歴の起点は読取先の上限ではなく、通常の認証済み履歴APIが読める範囲でたどれる。実操作と取得した保存済み会話は選択した審査Providerへ送信され、機微な情報を含み得る。履歴資格はProviderのMCP接続設定にだけ渡し、審査プロンプトやWithMateの保存ログには含めない。

## 一件の判定と手動承認

審査結果はアダプターの構造化チャネルから得た `decision: allow_once | deny | ask_user` と短い `reason` のみ。操作が欠ける、履歴を読めない、判断が曖昧、結果が不正、通信失敗、タイムアウトなどの場合は従来の承認を残す。自然文は許可の根拠にしない。

自動適用できるのは同じ保留要求の先頭一件だけ。ユーザーの手動解決、元操作・Turnの取消／終了、並行する承認要求、審査中のGUI入力や設定変更が先に確認された場合は、古い判定を適用しない。入力変更は経路をWithMateが分類せず、審査中に受け付けたGUI入力を保守的に扱う。手動操作は審査中も可能で、次の要求に使い回すのは会話の文脈だけである。
