# WithMate Auto Review

## 設定と適用範囲

Settings の `WithMate Auto Review` で `Review Provider`、`Review Model`、対応する場合は `Review Depth` を保存して、共通の審査エンジンを構成する。既定は `Off`。審査役はネイティブAuto Reviewと構造化出力を使えるClaudeまたはCodexで、選択先の通常の認証・利用枠を使用する。別モデル・別Providerへ切り替えない。

Copilot／OpenCodeのMain／Auxiliaryでは、`Approval` の `User / Auto Review` が手動判断とWithMate仲介審査を選ぶ。未指定（`Settings Default` 表示）で共通設定が `Off` の場合と、明示した `User` は従来の手動承認を使う。仲介を選んだ場合は構成済みエンジンに委譲可能な要求だけを渡し、未構成・使用不能・委譲不可（Providerが人間の判断を必須とする場合を含む）なら公開せず不許可とする。明示 `Auto Review` で共通設定が `Off` の場合も同じで、選択は保持する。旧保存値は未指定のままとし、自動審査を一括で停止したり個別の選択へ書き換えたりしない。Codex／Claudeはネイティブ審査を使う。通常Session MCP／CLIはcatalogで共通のApproval候補を列挙するが、作成・送信時の権限上書きは受け付けない。

## 審査会話と履歴の境界

要求元の WithMate 実行Turnで、審査できる実要求が来た時だけ審査会話を開く。審査が正常に完了した会話は同じTurn内で再利用し、後続の操作を別に判定する。Turnをまたがず、Turn終了・取消で審査会話を閉じる。Session接続は元Turnの通常の認証・失効に従う。通常のCrew子、審査会話の永続化、履歴のコピーは作らない。

審査の入力は実際の保留操作（Providerの引数・対象、既存要求から分かる影響）と要求元Session・世代・WithMate Turn。最初は本人の依頼、委譲経路、追加入力を調べ、後続では本人による元／親Sessionの新しい指示・訂正・撤回を読み、今回の操作に照らす。どの指示がこの操作を許すかの意味判断は審査役に委ねる。

審査役はClaude Code SDKまたはCodex App Serverの通常経路で起動し、組み込み指示で審査だけを担当させる。元の保留操作を審査するのはWithMateだが、審査役自身が行う操作の承認はClaudeの`auto`、またはCodexの`on-request`／`auto_review`に委ねる。WithMateは審査役の操作を承認しない。履歴は元Turnとして既存の認証済みSession APIから取得する。その起点は読取先の上限ではなく、通常のアクセス規則が適用される。実操作と取得した保存済み会話は選択した審査Providerへ送信され、機微な情報を含み得る。認証情報は通常の接続設定に渡し、審査プロンプトやWithMateの保存ログには含めない。

## 一件の判定と手動承認

組み込みの審査指示は、保留操作を実行せず、Session Graphの確認・記録など通常開発の定例手順を行わずに、必要な履歴だけを読むよう審査役に求める。実操作・本人の依頼・必要な委譲の根拠が欠ける、履歴を取得できない、委譲不可、または本人の指示に反する場合は拒否する。本人の最新依頼の通常手順や現行の許可範囲に対象・引数・影響が収まる場合は一件だけ許可する。必須の根拠と委譲可能性を確認したうえでなお本人の判断を要する場合だけ本人に確認する。

審査結果はアダプターの構造化チャネルから得た `decision: allow_once | deny | ask_user` と短い `reason` のみ。有効な `ask_user` だけが同じ先頭を手動承認として一度公開し、通知の対象とする。公開できない場合は不許可とする。操作・根拠の既知の欠落、審査不能、通信失敗、不正結果、期限切れや失効の場合は公開・通知せず、不許可として操作を実行しない。自然文は許可や手動復帰の根拠にしない。

同じ会話の保留要求は到着順に扱う。要求ごとの審査条件をその要求に保持し、先頭になったときと結果の適用直前に、同じ要求・Turn・設定・入力がまだ有効か照合する。後続の到着・取消だけでは先頭の判定は失効しない。審査待機・実行中は手動判断を受け付けず、自動許可・拒否で決着した要求は手動公開・通知しない。先頭が手動待ちなら自動で再試行せず、解決されるまで後続を審査しない。入力変更は経路をWithMateが分類せず、受け付けたGUI入力を保守的に扱う。次の要求に使い回すのは会話の文脈だけである。

審査中に保留要求が取り消された場合は、その審査会話の起動・実行を停止する。個別の要求取消だけでは元Turnを停止しない。Turn自体を取り消す操作は引き続き使える。停止が確認できれば、条件を満たす後続の先頭要求は新しい会話で審査する。元Turnが終わっても停止未確認の間は、同じ会話の次Turnで審査会話を開かない。Turnの終了・開始、従来の手動承認、別の会話は停止確認を待たない。停止を確認できないまま審査の期限に達した要求は公開せず不許可で決着し、後で停止が確認されても再試行しない。
